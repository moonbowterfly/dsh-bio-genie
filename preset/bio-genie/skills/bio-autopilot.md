# Autopilot 自主分析协议

> 目标：用户说一句话，你跑完整个分析；用户只在关键岔路口做决策。

## 何时启用

- 复杂需求（≥3 步、跨工具、有中间产物）→ 默认启用完整协议
- 简单请求（单工具可答，如"这段序列 GC 多少"）→ 直接做，不启用

## 流程

### 1. 分析计划（输出给用户）

```
《分析计划》
目标：……
步骤：
  1. bio_entrez_fetch 下载参考序列 → refs/
  2. bio_msa 多序列比对 → out/aln.fasta
  3. bio_phylo_build 建树 → figures/tree.png
预期产物：……
```

计划输出后**不要等用户确认**——除非计划本身有路线分叉（见决策点）。直接开跑。

### 2. 自动执行

- 无风险步骤（本地计算、检索、绘图）连续推进
- 每步失败按自主修复流程处理（最多 3 次）
- 中间产物写文件，不堆在回复里

### 3. 关键决策检查点（暂停，用 ask_user_question）

只有这些情况才打断用户：

| 决策点 | 示例 |
|---|---|
| 分析路线分叉 | "先差异表达还是先 GSEA？" |
| 阈值/参数取舍 | "padj cutoff 用 0.05 还是 0.01？" |
| 结果歧义 | "BLAST 前两个命中同源度相同，以哪个为准？" |
| 高成本操作 | "需要安装 scanpy（~2GB），继续吗？" |

提问规范：
- 一次把本轮所有决策点打包问完，不要挤牙膏
- 每个问题给出推荐选项，label 末尾加 `(Recommended)`
- 给出足够上下文，让用户不看日志也能拍板

### 4. 长任务目标管理（bio_goal）

预计超过 ~10 步的任务，先用 `bio_goal` 创建目标：

- `bio_goal({action:"create", objective:"…"})` — 框架持久化目标，追踪轮次预算
- 遇到需要用户输入的阻塞 → `bio_goal({action:"block", reason:"need-human-input: …"})`
- 用户回答后 → `resume` 继续
- 完成 → `complete`

### 5. 结果报告（固定格式）

```
《结果报告》
■ 结论：……
■ 溯源表：
  | 结论 | 来源工具 | 关键输出 |
■ 产物文件：……（绝对路径）
■ 参数记录：……（工具 + 参数 + 版本，可复现）
■ 后续建议：……（含可做的湿实验验证，如有）
```

## 禁忌

- ❌ 把"自动执行"理解成"所有步骤都问一遍"——那是逐句问答，不是 autopilot
- ❌ 在决策点替用户拍板高风险选择（路线/阈值）——给出推荐但等确认
- ❌ 报告里出现无溯源数字——rigor-guard 会打回
